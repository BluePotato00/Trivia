# Trivia — Web Edition (no server required)

A fully client-side, offline version that runs by just double-clicking
`index.html` — no local server, no build step, no internet connection
needed once it's set up.

- **Player 1 buzzes in with the `Z` key** (or by clicking the on-screen button).
- **Player 2 buzzes in with the `M` key** (or clicking).
- Same rules as every other version: 10-second countdown, 3-second
  answer reveal if nobody buzzes, verbal answers with a Reveal Solution
  button, Correct/Incorrect scoring, Next Clue, Reset Game.

## Why this needed a different approach than "just fetch the data"

Opening an HTML file directly from disk (`file://...`) causes most
browsers — Chrome in particular — to block `fetch()`/`XMLHttpRequest`
calls to local files as a security measure. A typical web app that
tries to `fetch('clues.json')` on load will silently fail or throw a
CORS error when run this way, with no server involved to configure
around it.

The workaround: `clues_data.js` isn't fetched — it's loaded with a
plain `<script src="clues_data.js">` tag, the same way `game.js` and
`style.css` are loaded. Script and stylesheet tags aren't subject to
that restriction, so the whole game, data included, just works from a
double-clicked file in every major browser.

## 1. Generate clue data files from your existing database

Reuse the same corrected `clues.db` from the Android/macOS versions —
no changes needed to the file itself:

```bash
python3 convert_clues_to_js.py /path/to/clues.db .
```

This produces multiple files — `clues_data_part1.js`,
`clues_data_part2.js`, etc., plus `clues_manifest.js` — instead of one
big file. Each part is kept under 20MB, safely under GitHub's 25MB
web-upload limit for individual files (a single ~90MB file, like an
earlier version of this script produced, gets rejected by GitHub's
drag-and-drop uploader with a "that's a big file" error). `game.js`
reads `clues_manifest.js` at startup and loads every part listed in it,
in order, so the exact number of parts doesn't matter — just make sure
**all** of them end up in the same folder as `index.html`.

This must be run before opening `index.html` for the first time —
without these files present, the page will load fine but show an
in-app error (via the same "no clues" / diagnostic pattern the Android
version uses) rather than crashing silently.

## 2. Run it

Just double-click `index.html`, or drag it into any browser window.
That's it — no server, no `npm install`, nothing else to set up.

## Files

| File | Purpose |
|---|---|
| `index.html` | Page structure |
| `style.css` | Jeopardy blue/gold/white styling, same palette as the other versions |
| `game.js` | Game logic — buzz-in, countdown, scoring, phases |
| `convert_clues_to_js.py` | One-time conversion script (run locally, not in a browser) |
| `clues_data.js` | Generated by the script above — not included, you create it |

## Getting it onto an iPhone as a permanent, offline home-screen icon

iOS Safari doesn't handle local multi-file `file://` pages reliably (it's
gotten stricter over recent iOS versions), so getting this working on an
iPhone needs one extra step — but the result is a real home-screen icon
that works fully offline afterward, with no app-signing or expiration
involved at all, since it's just a bookmark, not an installed binary.

This project already includes a Service Worker (`sw.js`) and a web app
manifest (`manifest.json`) that cache every file — HTML, CSS, JS, and
your entire clue database — the first time the page loads. After that
first load, it works with zero network access.

The one catch: Service Workers require a secure context (HTTPS, or
`localhost`) — a plain local network address like `http://192.168.x.x`
won't qualify. So the first load needs to happen over HTTPS once:

1. Host this folder somewhere with automatic HTTPS — GitHub Pages is
   free and simple for this (create a repo, upload these files —
   `index.html`, `style.css`, `game.js`, `sw.js`, `manifest.json`, the
   icon PNGs, and **all** of your generated `clues_data_partN.js` files
   plus `clues_manifest.js` — then enable Pages in the repo settings).
2. Visit that HTTPS URL once in Safari on your iPhone. The service
   worker silently caches everything.
3. Tap Share > Add to Home Screen. This creates a standalone app-like
   icon — no Safari chrome when launched.
4. From then on, it works with WiFi off, no Mac, no GitHub — the icon
   just works.

**Privacy note:** GitHub Pages sites are public by default, meaning
your scraped clue data would technically be reachable by anyone with
the URL. Fine for personal use, but if that matters to you, look into
a private hosting alternative or a self-signed local HTTPS certificate
instead.

If you ever regenerate the clue data files with new clues, bump the
`CACHE_NAME` version string at the top of `sw.js` (e.g. `v1` → `v2`) and
reload once while online — that forces the cached copies to refresh.



- Works in Chrome, Firefox, Safari, and Edge. Since it's plain HTML/CSS/
  JS with no framework or build tooling, there's nothing to install to
  view the source or make tweaks either.
- If you ever want to host this on an actual web server instead (e.g.
  a school or home server), it'll work exactly the same way — the
  script-tag approach isn't a server-only or file-only trick, it works
  in both contexts identically.
- The generated `clues_data.js` will be a large-ish text file since it
  embeds your entire clue set directly — that's expected and is what
  makes the "no server, no fetch" approach possible in the first place.
